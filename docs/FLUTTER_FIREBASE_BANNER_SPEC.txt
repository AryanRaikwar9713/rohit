================================================================================
FLUTTER – FIREBASE BANNER / AUTO NOTIFICATIONS (FOR CURSOR)
================================================================================
Backend already sends FCM with notification (title, body) + data. Use this file
so Flutter shows banner (app open/closed) and on tap opens the right screen.
================================================================================

--------------------------------------------------------------------------------
1) FCM TOPICS – SUBSCRIBE ON LOGIN
--------------------------------------------------------------------------------
After login, subscribe to BOTH:
  - FirebaseMessaging.instance.subscribeToTopic('user_${userId}');
  - FirebaseMessaging.instance.subscribeToTopic('all_users');

On logout, unsubscribe from both.
Without this, no push will be received.

--------------------------------------------------------------------------------
2) BANNER / POPUP – APP CLOSED OR BACKGROUND
--------------------------------------------------------------------------------
Backend sends BOTH "notification" and "data" in FCM. So:
  - When app is in background or killed: OS shows the banner/popup automatically
    (title + body). No extra Flutter code needed for the system banner.
  - When app is in foreground: you can show an in-app banner (e.g. overlay or
    snackbar) using the title/body from the RemoteMessage, then on tap navigate.

Implementation outline:
  - FirebaseMessaging.onBackgroundMessage: handle data-only if needed; for
    notification+data, OS usually shows the notification. You can still
    schedule a local notification with the same title/body for consistency.
  - FirebaseMessaging.onMessage: app in foreground – show in-app banner/snackbar
    with message.notification?.title and message.notification?.body, and
    message.data for tap (navigate to screen).
  - FirebaseMessaging.onMessageOpenedApp: user tapped notification (app was
    background) – use message.data to navigate.
  - FirebaseMessaging.getInitialMessage: app opened from killed state by tap –
    use message.data to navigate.

5) BACKEND – WHAT SENDS EACH TYPE (REFERENCE)
--------------------------------------------------------------------------------
message         → message/send_message.php
like, comment, share → post_likes.php, post_comments.php, post_share.php
post_upload     → upload_posts.php (followers)
reel_like, reel_comment → reels/reel_like.php, reels/add_comment.php
reel_upload     → reels/create_reel.php (followers)
story_upload    → story_api.php (followers)
long_upload     → long_video_api.php action=upload (followers)
long_like       → long_video_api.php action=long_video_like
long_comment    → long_video_api.php action=long_video_comment
follow          → follow_api.php
impact_project  → impact/social_impact_api.php createProject (followers)
impact_donated  → impact/donate.php
impact_viewed   → impact/get_projects.php (single project view)
admin_broadcast → admin panel Send notification (one user or all_users topic)

6) LONG VIDEO – NEW API ACTIONS (FLUTTER CALL THESE)
--------------------------------------------------------------------------------
Like:  POST long_video_api.php?action=long_video_like  (video_id, auth)
Comment: POST long_video_api.php?action=long_video_comment (video_id, body or comment, auth)

Response: { "success": true, "message": "Liked" } / { "success": true, "message": "Comment added", "comment_id": ... }

7) IN-APP NOTIFICATION LIST (ALREADY FROM BACKEND)
--------------------------------------------------------------------------------
GET api/notification-list (Bearer token) → notification_data, all_unread_count.
POST api/notification-mark-read → mark all read.
POST api/notification-mark-read/{id} → mark one read.

Use for the Notification page; badge = all_unread_count.
